\section{What This Final Chapter Is For}

The previous chapters introduced a sequence of modeling ideas:

\[
  \text{CNNs}
  \rightarrow
  \text{linear systems}
  \rightarrow
  \text{SSMs}
  \rightarrow
  \text{HiPPO}
  \rightarrow
  \text{S4}
  \rightarrow
  \text{S5}
  \rightarrow
  \text{Mamba}.
\]

This chapter turns that chain into modeling judgment. The goal is not to crown one model
family as universally best. The goal is to understand what each family is good at, what it
costs, and why S5 and Mamba are credible backbones for causal Utah-array self-supervised
learning.

\section{The Basic Families}

We now have six useful reference points:

\paragraph{CNNs.}
Temporal CNNs apply fixed finite filters across time. They are parallel, simple, and good
at local pattern extraction.

\paragraph{RNNs.}
RNNs update a hidden state one step at a time. They are naturally online but harder to
parallelize across time.

\paragraph{Transformers.}
Transformers mix positions through content-dependent attention. They are flexible and
powerful, but long-context causal attention is expensive.

\paragraph{S4.}
S4 uses a structured LTI SSM to generate long convolution kernels from learned dynamics.

\paragraph{S5.}
S5 simplifies S4 to diagonal dynamics, MIMO channel handling, and parallel scan.

\paragraph{Mamba.}
Mamba adds input-dependent selectivity to the SSM update while preserving linear-time
scan-style computation.

\section{Axis 1: How Temporal Information Is Mixed}

Each family has a different answer to the question:
\[
  \text{How does the output at time } t \text{ access relevant information from the past?}
\]

\paragraph{CNN.}
By a fixed local or dilated receptive field.

\paragraph{RNN.}
By whatever survives in the hidden state after sequential updates.

\paragraph{Transformer.}
By direct pairwise lookup with content-dependent weights.

\paragraph{S4 and S5.}
By a structured recurrent memory whose effect can also be read as a long convolution.

\paragraph{Mamba.}
By a structured recurrent memory whose update rule itself depends on the current input.

This is why Mamba should not be described as ``just S5 but bigger.'' The key change is not
size. It is the move from fixed dynamics to selective dynamics.

\section{Axis 2: Parallel Training}

Parallel training matters because long-sequence models are expensive even before one starts
hyperparameter search.

CNNs parallelize naturally because each output position is just a local filter application.
Transformers parallelize over positions during training, though attention still has high
memory and compute cost.

Vanilla RNNs are the weakest here. Their recurrence is intrinsically sequential in the
obvious implementation.

S4 and S5 improve on this in different ways:

\begin{itemize}
  \item S4 exploits the convolutional view of LTI SSMs.
  \item S5 exploits scan over structured recurrence updates.
  \item Mamba uses selective scan after giving up the fixed-kernel view.
\end{itemize}

So the real divide is not ``recurrent'' versus ``parallel.'' Modern SSMs show that a model
can be recurrent in interpretation but still train with substantial parallelism.

\section{Axis 3: Online Inference}

For a causal neural decoder, online inference matters. The system should be able to process
new bins left to right without re-reading the full history.

CNNs can be run causally, but without an explicit compact state they either recompute from
recent context windows or rely on limited receptive fields.

RNNs, S4, S5, and Mamba all have a fixed-size recurrent state:
\[
  \vx_t \in \R^N \text{ or } \C^N.
\]
That is attractive for deployment because memory does not grow with the full past context.

Transformers can cache keys and values, which helps runtime, but the cache still grows with
context length. For very long or continuous streaming settings, that can become awkward.

This deployment distinction is one reason SSMs remain attractive even when transformer
baselines are strong.

\section{Axis 4: Long Memory}

Long memory is not just about seeing many previous steps. It is about representing them in
a way that is useful and stable.

CNNs can extend context through depth, dilation, or large kernels, but the memory remains
filter-based and usually finite.

RNNs can in principle store arbitrary summaries, but optimization makes long memory hard.

Transformers have direct access to long context, but this comes with quadratic interaction
structure and heavy memory use.

S4 and S5 are explicitly designed to maintain long-range memory through learned dynamical
modes. HiPPO-inspired initialization is part of why this works. Instead of hoping the model
discovers a good long-memory spectrum from scratch, these architectures start from one.

Mamba inherits the long-memory state-space story but adds the ability to modulate that
memory according to the input.

\section{Axis 5: Content Dependence}

This is one of the sharpest distinctions among model families.

\paragraph{Weak content dependence.}
CNNs and LTI SSMs use fixed temporal mixing rules. The input changes the state values or
activations, but the temporal operator itself is fixed after training.

\paragraph{Strong content dependence.}
Transformers compute pairwise weights from the current content.

\paragraph{Intermediate selective dependence.}
Mamba changes the recurrent update according to the input, but it does not form arbitrary
pairwise attention maps.

This is why the practical comparison between S5 and Mamba is often the most meaningful:

\[
\begin{array}{lll}
\text{S5} &:& \text{cleaner fixed dynamics, easier modal interpretation}, \\
\text{Mamba} &:& \text{more flexible memory control, less clean kernel interpretation}.
\end{array}
\]

\section{Axis 6: Interpretability}

Interpretability here means something modest: how naturally can we describe what the model
is doing as a dynamical system?

S4 and S5 are relatively interpretable by SSM standards because their temporal core has a
fixed mode structure. One can talk about decays, oscillations, timescales, and impulse
responses.

Mamba is harder to summarize because the dynamics depend on the input. The same model can
behave differently at different sequence positions even if the abstract state size is the
same.

Transformers are interpretable in a different way: one can inspect attention maps and
token-token interactions, though this is not always as transparent as people hope.

For scientific neural data, this matters. If the goal includes understanding temporal
structure in addition to maximizing decoding accuracy, fixed-dynamics SSMs may have an
advantage as analysis tools.

\section{Axis 7: Parameter Efficiency And Capacity}

A direct learned long convolution kernel has parameter count tied to kernel length. An SSM
instead uses a compact state:
\[
  \mK_i = \mC\bar{\mA}^i\bar{\mB}.
\]
So capacity is distributed differently:

\begin{itemize}
  \item model width controls feature representation;
  \item state size controls dynamical richness;
  \item depth controls how many such transformations are composed.
\end{itemize}

This is an attractive design for long sequences because increasing context length does not
require directly learning ever-longer free kernels.

The flip side is inductive bias. A small state cannot represent arbitrary long kernels. It
represents kernels consistent with the learned dynamics. When that bias matches the data,
the model is efficient. When it does not, the model can be constrained.

\section{What Matters For Utah Array SSL}

Now narrow the discussion to the actual project. The local setup is not generic language
modeling. It is self-supervised learning over Utah-array neural time series, with transfer
to speech-relevant downstream decoding.

That changes the priorities.

\paragraph{Causality matters.}
The eventual decoder should operate causally. S5 and Mamba both support that naturally.

\paragraph{Streaming matters.}
Fixed-size recurrent state is attractive for eventual online use.

\paragraph{Temporal dynamics matter.}
The data are continuous neural signals, not symbolic tokens. A dynamical inductive bias is
plausible.

\paragraph{Content dependence may still matter.}
Even though the data are time series, not text, the model may still need to respond
differently to different neural events. That is the main architectural reason to keep
Mamba in scope.

\paragraph{Objective design matters as much as backbone choice.}
The local notes already show that shortcut-friendly SSL metrics can be misleading. A strong
backbone does not rescue a weak objective.

\section{Raw Bins Versus Patches}

One recurring design choice in the local notes is whether to feed raw $20$ ms bins or
causal temporal patches. This is not unique to SSMs, but SSMs interact with it in an
interesting way.

Raw bins preserve fine timing. Patches may improve local context aggregation and reduce
sequence length. For S5 and Mamba, both are defensible:

\begin{itemize}
  \item if the temporal operator is already strong, raw bins may be sufficient;
  \item if local structure is noisy, causal patches may give the backbone cleaner inputs;
  \item the best choice may depend on SSL objective and downstream probe behavior.
\end{itemize}

This is why the project's architecture grid of raw-bin and patch-based inputs is sensible.
It separates input representation questions from backbone-family questions.

\section{Subject And Session Variation}

The local project also emphasizes subject- and session-level adaptation. That is a real
issue for neural data. A sequence backbone alone should not be expected to absorb all cross-
session drift.

This matters for interpreting architecture results. If a backbone underperforms, the cause
may not be that the temporal inductive bias is wrong. It may be that input alignment is too
weak, nuisance structure dominates, or the SSL objective encourages context shortcuts.

So a fair S5-versus-Mamba comparison should hold the front-end adaptation, normalization,
and evaluation protocol as constant as possible.

\section{What S5 Is Best For In This Project}

S5 is a strong choice when the priority is:

\begin{itemize}
  \item a clean causal SSM baseline;
  \item stable long-memory dynamics with interpretable modes;
  \item relatively simple implementation compared with S4;
  \item a backbone whose failures are easier to diagnose mechanistically.
\end{itemize}

For SSL experiments, that last point matters. If the representation geometry collapses or
the model learns only local shard context, S5 is often easier to reason about than a more
selective architecture.

\section{What Mamba Is Best For In This Project}

Mamba is a strong choice when the priority is:

\begin{itemize}
  \item content-sensitive temporal processing;
  \item stronger ability to modulate memory according to the neural signal;
  \item long-context scaling without full attention cost;
  \item a second SSM-family baseline that is meaningfully different from S5 rather than
  just a small variant.
\end{itemize}

It is especially worth testing if fixed-dynamics models appear too rigid for the SSL task
or if one suspects the model needs to gate memory differently around salient neural events.

\section{Why Not Default To Transformers Here?}

Transformers are a reasonable baseline, and the broader BCI literature already contains
strong transformer-style results. But this project is not only trying to maximize a generic
benchmark score. It is also investigating whether speech-related Utah-array activity is
better modeled as a latent dynamical system.

That is a serious modeling question, not just a performance gamble. If an SSM family can
match or approach transformer-level downstream utility while giving cleaner online-state
semantics and better streaming behavior, that is scientifically and practically meaningful.

\section{Practical Decision Rule}

If forced to choose among these families for this specific project, a reasonable pragmatic
rule is:

\begin{enumerate}
  \item Use S5 as the clean fixed-dynamics SSM baseline.
  \item Use Mamba as the selective SSM comparison.
  \item Keep transformers as an external reference class, not necessarily the main
  architecture family under current investigation.
\end{enumerate}

This lines up with the local notes: S5 and Mamba are not redundant choices. They test two
different hypotheses about what kind of memory mechanism neural SSL needs.

\section{Exit Criteria For Understanding}

After these notes, you should be able to answer the following without hand-waving:

\begin{itemize}
  \item Why is a convolution a natural precursor to an SSM?
  \item What does HiPPO contribute that a random recurrent matrix does not?
  \item Why is S4 more complicated than S5?
  \item Why does Mamba lose the fixed convolution kernel?
  \item In what sense is Mamba more content-aware than S5 but less explicit than
  attention?
  \item Why are S5 and Mamba both plausible for causal Utah-array SSL?
\end{itemize}

If those answers are clear, you are ready to read the papers directly and compare their
fit for the project at a technical level rather than by branding or hype.

\section{What To Remember}

\begin{itemize}
  \item CNNs, RNNs, transformers, S4, S5, and Mamba differ mainly in how they mix
  information across time.
  \item SSMs are attractive because they combine recurrent state with efficient training
  and fixed-size online memory.
  \item S4 emphasizes structured long kernels; S5 emphasizes simpler diagonal/MIMO scan;
  Mamba emphasizes selective input-dependent memory updates.
  \item For Utah-array SSL, architecture choice matters, but objective design and nuisance
  control matter just as much.
  \item S5 and Mamba test genuinely different temporal hypotheses and are both worth
  studying in this project.
\end{itemize}
